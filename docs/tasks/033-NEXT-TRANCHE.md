Status: review-ready recommendation from the exact Task 033 audit and provider

## Decision

Select one immediate product tranche: **Task 040, the Cinderwheel canonical
vertical slice**. The tranche is intentionally one task wide. It must consume
the accepted graph, instrument, performance-control, target/backend, and
provider authorities rather than create a parallel prototype shelf.

No Mutable-derived implementation and no JUCE `juce_dsp` class is selected as
implementation authority for Task 040. Cinderwheel remains a `new-design`
instrument. Its validated prototype is an oracle and source of promotion
requirements, not a canonical component, provider, graph, target, or evidence
record.

## Why this tranche is bounded

Task 033 closes the seven-entry native provider authority, but Cinderwheel needs
nine unresolved local roles, an executable performance-control path, and an
exact production-model decomposition. Padding the tranche with unrelated
Mutable promotions or a JUCE provider would increase surface area without
closing the first canonical musical workflow.

Task 040 may conclude that one or more Cinderwheel roles should remain inside
an inspectable instrument-owned compound rather than become default palette
objects. It may promote a reusable primitive only after the live allocation
audit proves exact semantics, reuse, provider placement, and graph
inspectability. The tranche therefore permits a shortfall instead of inventing
objects to meet a count.

## Required proof before any promotion

- Exact accepted parent record set, stable-ID allocation, and live worktree
  must be frozen on activation.
- Every public node needs a target-independent component contract before a
  binding, eligibility, provider entry, or runtime factory descriptor.
- Float prototype behavior and the current fixed-Q27 provider are not
  equivalent by implication. Numeric ownership and any conversion must be
  explicit.
- The complete fused prototype topology must remain inspectable even when a
  canonical implementation owns several local roles.
- The canonical performance configuration must reference public instrument
  facets; the Launch Control 3 map may not target DSP node IDs directly.
- Objective host-signal parity, native build, real-time timing, physical MIDI,
  listening, distribution, and production acceptance are separately promoted
  gates.
